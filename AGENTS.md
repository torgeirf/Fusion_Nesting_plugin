# Notes for AI agents

Sheet Nester is an Autodesk Fusion add-in (Python) that lays flat panels on stock sheets and nests them for CNC cutting. The user-facing docs are in `README.md`; this file covers what you need to change the code safely.

## Layout

```
SheetNester/              the add-in; Fusion requires folder name == manifest name == main .py name
  SheetNester.py          run()/stop() entry points only
  SheetNester.manifest
  sn_command.py           command definition, dialog inputs, preview/execute, summary
  sn_parts.py             Fusion body -> PartInfo: thickness axis, lay-flat basis, flat outline
  sn_layout.py            builds the "Nest Layout" component, sketches, labels, DXF/CSV export
  nestcore/               pure-Python nesting engine (NO Fusion imports)
    nester.py             NestPart/NestOptions/NestResult, search driver, both engines
    rectpack.py           MaxRects bin packing
    raster.py             bitmap (big-int rows) collision model for true-shape nesting
    geometry.py           2D helpers
  resources/              toolbar icons (generated by tools/make_icons.py)
tests/                    unittest suites (run outside Fusion)
tools/make_icons.py       regenerates the PNG icons, stdlib only
```

## Hard rules

- `nestcore` must never import `adsk`. It is tested outside Fusion, and keeping it pure is what makes the engine verifiable.
- Inside the add-in, use relative imports (`from . import sn_parts`). Fusion loads the add-in as a package.
- Fusion runs the add-in on its bundled Python (3.14 as of Oct 2026). Use stdlib only; nothing can be pip-installed for users.
- Fusion's internal length unit is **centimetres**. All geometry and every `ValueCommandInput.value` is in cm; format for display with `design.unitsManager.formatValue`.

## Testing

```bash
python -m unittest discover tests
```

- `tests/test_nestcore.py` checks every layout geometrically: margins, minimum spacing between parts, no overlap, sheet counts.
- `tests/test_lay_flat.py` installs a fake `adsk` module and checks the orientation and placement-matrix chain on a tilted, chamfered panel.
- Fusion's own interpreter can run the tests too: `%LOCALAPPDATA%\Autodesk\webdeploy\production\<hash>\Python\python.exe`.

**Code that touches the Fusion API cannot run here.** Say so plainly when you change it, and ask the user to test in Fusion (`Shift+S` → Add-Ins → select SheetNester → **Stop**, then **Run**, to reload).

## Checking Fusion API usage without Fusion

Fusion ships type stubs with docstrings at:

```
%LOCALAPPDATA%\Autodesk\webdeploy\production\<hash>\Api\Python\packages\adsk\defs\adsk\{core,fusion}.py
```

The `<hash>` folder changes with each Fusion update; pick the newest one that contains `Api`. Grep the stubs before using any API member. Names have changed between versions: for example, `SketchTexts.createInput2` is gone (use `createInput3`), sketches use `project2`, and there is no `Sketch.saveAsDXF` (use `exportManager.createDXFSketchExportOptions`).

To type-check against the stubs, install mypy in a scratch venv and run:

```bash
MYPYPATH=<...>/adsk/defs mypy --check-untyped-defs --ignore-missing-imports --follow-imports=silent -p SheetNester
```

Some errors are expected false positives:

- `"CommandInput" has no attribute "value"`: `itemById` returns the concrete input type at runtime.
- `int` passed where an enum type is expected.
- `ToolbarControl.isPromoted`.
- "Need type annotation" in `nestcore`.

## Fusion gotchas that this code relies on

- **Keep event handler objects referenced**, or they get garbage-collected. See `_handlers` and `_cmd_handlers` in `sn_command.py`.
- **Don't open modal dialogs (messageBox, folder dialog) inside the command's execute handler.** The command stays "running" and the busy cursor spins until the dialog closes. Execute stores results in `_pending` and fires the custom event `SheetNester_AfterNest`; `_on_after_nest` then shows the folder dialog and the summary once Fusion is idle.
- **Base features (parametric designs):** body references returned by `bRepBodies.add(temp, baseFeature)` are not valid after `finishEdit()`. Re-fetch them by name (`_add_bodies` in `sn_layout.py`). Direct-modelling designs have no base feature.
- **`TemporaryBRepManager.copy()` of a proxy body** may or may not be in world coordinates. `_align_to_world` compares bounding boxes and applies `occurrence.transform2` if needed. All analysis works on the aligned temporary copy, so the outline and the placement matrix stay consistent.
- **Flat outline:** `TemporaryBRepManager.createProjectedBodyOutline(body, plane, tol)` gives the true silhouette, so chamfers, bevels and through-holes are handled. The fallbacks are mesh triangles, then the convex hull of the vertices.
- **Layouts are found by the attribute** `SheetNester/layout` on the component, not by name. `is_layout_body` uses it to keep layout bodies out of selections.

## Engine conventions (nestcore)

- **Sheet space:** X is the long side, Y the short side, origin at the lower-left corner. A placement maps a part's base-frame point `p` to `rotate(p, rotation) + (x, y)`. `Placement.bbox` is in sheet space.
- **Part frame:** `sn_parts.analyze` rotates each part by `PartInfo.angle` (from its minimum-area rectangle) so its long side lies along X. `PartInfo.matrix(rotation, x, y)` composes the basis, the base angle, the placement rotation and the translation.
- **Algorithm space:** both engines always fill along X while keeping Y low. Filling along the short side (`fill='short'`) is done by transposing the problem: geometry is swapped (x, y) → (y, x) after rotation, and `_Context.to_placement` swaps the result back.
- **Raster cell sets** are conservative: every touched cell is marked, and dilation is by spacing/2 + tolerance. Disjoint cell sets therefore guarantee the real spacing. Keep this property if you change `raster.py`; the layout checks in the tests depend on it.
- **Shape input:** `NestPart` takes `polys` (convex pieces; union), `outlines` (polylines filled even-odd, so holes stay open), or both.
- **Choosing a result:** among attempts, the best is lowest `(unplaced count, sheet count, extent used on the last sheet, total extent)`.

## Status (as of 2026-10-24)

- The user ran the add-in once in Fusion on a speaker cabinet and nesting completed. Their only report was the busy cursor during the summary dialog; it has been fixed (custom event) but not yet re-tested in Fusion.
- Not yet confirmed in Fusion: DXF export, label placement on the offset plane, the outline sketch (`project2` of bodies), and direct-modelling (non-parametric) designs.
